**Status: v0 development draft.** Formats and IDs may change until v1.

## Trust the catalogue accordingly

Every catalogue record was generated by Gemini from [wger](https://wger.de) community data. No person has checked them. Each one says so in `provenance.review` and lists the values in `provenance.generated`. Reviewing is the main way to contribute.

## Use it

Apps should pin a [release](https://github.com/openexercise/open-exercise/releases) and read [GUIDE.md](GUIDE.md) and the [developer guide](docs/developer-guide.md). To work on the repository ([CONTRIBUTING.md](CONTRIBUTING.md) has the rest):

```bash
go run ./cmd/oes validate
go test ./...
go run ./cmd/oes site dist
```

`validate` checks the examples and catalogue against the schema, vocabularies and cross-record rules. `site` builds the static website into `dist`.

The first import generated records with Vertex AI, which needs Google Cloud credentials and `OES_GCP_PROJECT`. `sources/enrichment` and `sources/relations` keep each model answer, so `merge` needs no credentials. Records have been edited by hand since, and `merge` rebuilds `catalogue/exercises` from those answers, discarding every later change, so it's kept as history: don't run it to contribute.

```bash
go run ./cmd/enrich generate
go run ./cmd/enrich relate
go run ./cmd/enrich merge
```
